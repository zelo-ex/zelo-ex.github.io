* 1.1 程序设计的基本元素

** Scheme概述

Scheme属于一种Lisp方言，有Lisp的大部分特性。

Scheme并不是解释型语言，它同时包含一个编译器与解释器，允许混合使用。
+ 在“读入-求值-打印循环(REPL)”中即时测试和修改代码
+ 通过编译获得近乎底层语言的执行速度

Scheme普遍采用前缀表达法，代码以S-表达式(S-Expression)书写。

Scheme区分数字类型，有精确整数、精确有理数、不精确实数等。
+ Scheme将数字分为两个维度
  + 精确性 (exact/inexact)
    描述的是用什么方式表示数
    exact 计算过程不产生舍入误差
    inexact 计算过程产生舍入误差
  + 数学类型 (integer/rational/real/complex)
    描述的是其在数学上是什么数
    integer 整数
    rational 有理数
    real 实数
    complex 复数

** 过程应用的代换模型（简称“代换模型”）

将过程体中的每一个形参用相应实参取代后，对整个过程体求值。
代换模型适合解释纯函数式语言，对于“变化的数据”应该考虑环境模型。

其包含两种求值策略
+ 应用序（applicative order）
  先对实参求值后，将值代换形参进行求值
+ 正则序（normal order）
  先将实参代换形参，然后对代换后的表达式求值
注意，Lisp采用应用序求值，但特殊情况下不是常规的应用序，如if、conf、and、or等。
原因：避免对于表达式的重复求值。

#+BEGIN_SRC scheme
  (define (p) (p))

  (define (test x y)
    (if (= x 0) 0 y))

  (test 0 (p))
#+END_SRC
在上述例子中，如果解释器采用正则序就会产生递归调用，而应用序则不会。

** 条件表达式和谓语

+ 谓语 (predicate)
  判断真假的过程，如 =even?= 等
  Scheme里面只有 =#f= 解释为假，其余都是真
+ 谓语调用 (predicate application)
  调用谓语得到的表达式，如 =(even? x)=
+ 条件 (condition)
  条件表达式里面用来判断真假的子表达式
  如 =(if (even? x) ...)= 里面的 =(even? x)=
+ 条件表达式 (conditional expression)
  指整个if/cond表达式 

** 过程作为黑盒抽象

+ 约束变量 (bound variable, 又称“绑定变量”)
  在某个绑定结构中被引入，并在其作用域内被绑定的变量，例如：
  + =lambda= 的形参
  + =define= 定义过程时的形参
  + =let= / =let*= / =letrec= 的绑定变量
  + 内部 =define= 的变量
  绑定持续到顶层环境销毁或程序结束，在绑定时仍然可以改变值
+ 自由变量 (free variable)
  在一个表达式或过程体内，没有被该表达式或过程体绑定的变量。
  注意是相对于当前表达式，它没有被当前表达式绑定，即可能被外层环境绑定
+ 未绑定变量 (unbound variable)
  运行时在定义环境里找不到绑定的自由变量，调用/使用未绑定变量属于非法行为
  绑定必须在该变量的词法作用域内，并且运行时使用它时已经建立才属于合法行为

#+BEGIN_SRC scheme
  (define (f x)
    (+ x y))

  (define (g)
    (define y 10)
    (f 5))

  (g)
#+END_SRC
对于上述代码， =f= 定义在全局环境，它的自由变量 =y= 会去全局环境找。
=g= 内部的 =(define y 10)= 是 =g= 的局部绑定，不在 =f= 的定义环境里。
因此 =(g)= 会报错，说明这种行为是非法行为。

+ 词法作用域 (lexical scoping)
  过程体内的变量应到过程定义时所在的环境里找，而不是到调用时所在的环境里找。
  与动态作用域不同，词法作用域让过程的行为只依赖定义位置，不依赖调用位置。
  使代码行为可预测

* 1.2 过程及其产生的计算

** 线性的递归和迭代

+ 递归计算过程 (recursive procedure) 与递归过程 (recursive process)
  递归过程是过程定义中语法层面上直接或间接调用了自身。
  递归计算过程是在运行时求值留下了未完成操作，
  由于需要维护不断增长的延迟操作链，栈随深度增长，有额外空间消耗

+ 尾递归 (tail recursion)
  在Scheme中，尾递归过程产生迭代计算过程，但是形式上为递归过程。
  但尾递归为迭代计算过程的前提为编程语言支持尾递归优化，
  如仍然有额外栈空间消耗，则在该语言中，尾递归属于递归计算过程。
